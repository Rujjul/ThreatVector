## Sharing labels and copyright

[FIRST's TLP guidance](https://www.first.org/tlp/) distinguishes sharing boundaries from copyright permission. CISA's own PDFs also retain that qualification. Preserve original TLP labels in metadata; do not treat WHITE/CLEAR as CC0, an open-content license, or permission to redistribute embedded third-party material. CISA software's public-domain policy was not used to clear advisory prose.

The selected CISA texts are government-coauthored, but this review does not assume that all embedded material is government-owned or that U.S. public-domain treatment settles international rights. The committed representation uses facts restated in original language. Source PDFs, extracted text, HTML policies and the complete ATT&CK bundle remain local under ignored `data/raw/source-review/`.

## Provenance and correlation review

- NVD records were retrieved individually through `cveId`; selection is explicit, not a sample claimed representative of the full NVD. API response bytes and selected canonical record hashes are measured separately.
- ATT&CK JSON and the license were fetched using the resolved immutable commit, not a moving branch. The raw bundle is 39,787,657 bytes; only two reviewed technique summaries enter this fixture.
- AA22-320A page 2 identifies CVE-2021-44228 in the overview and maps its reported initial access to T1190. The same page separately labels PowerShell execution T1059.001. The advisory says it uses ATT&CK version 12; that historical version is retained independently of this fixture's release-17.1 technique definitions.
- AA22-174A page 1 explicitly identifies CVE-2021-44228. Neither selected PDF's extracted text contains `45046`; this bounded check does **not** prove that CVE-2021-45046 was never exploited elsewhere.
- CVE-2021-45046's NVD description explicitly refers to the incomplete fix for CVE-2021-44228. This is a vulnerability-to-vulnerability relationship, not evidence of its use in either report.
- Dates come from the API fields or PDF cover pages, not search-engine crawl dates. ATT&CK STIX creation/modification timestamps are separate fields; unavailable publication dates remain `null`.
- Sections are manually curated evidence units, not tokenizer-generated retrieval chunks. No token limits, retrieval relevance, ANN quality or benchmark performance have been measured.

## Before expanding the corpus

Review each proposed report and its own license, coauthors, sharing label and third-party notices. Record the exact terms URL, date, artifact hash and redistribution decision. Keep ambiguous sources link-only or use original factual summaries; obtain permission before distributing original text where needed. Recheck NVD bulk-access guidance, retain attribution, use bounded requests and preserve a deterministic snapshot. Do not silently replace unavailable sources with unrelated material.

The source-review manifest records successful downloads and failed/JavaScript-shell policy checks separately. An HTTP 200 alone is not recorded as successful review of policy content. No authentication, secrets, payment, crawling or publisher contact was involved.
